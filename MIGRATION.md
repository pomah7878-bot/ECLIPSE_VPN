# 🚚 Переезд бота на другой сервер

Пошаговая инструкция для администратора: как перенести ECLIPSE Unlimited VPN с одного сервера на другой **без потери клиентов, ключей, баланса и настроек**. Переезд занимает 15–30 минут, бот не будет работать только в момент переключения (несколько минут).

> Если вы просто обновляете бота — переезд не нужен. Обновление делается кнопкой **🔄 Обновить бота** в админке.

---

## 0. Что именно переносится

| Что | Где лежит | Попадает в Telegram-бэкап? |
|---|---|---|
| База бота (клиенты, ключи, тарифы, баланс, платежи, настройки, лицензия, токены интеграций) | `database/vpn_bot.db` | ✅ да |
| Токен бота и список админов | `config.py` | ❌ **нет** |
| Ключи AI, секреты OAuth/Turnstile/Zvonok, `LICENSE_KEY` | `secrets.env` | ❌ **нет** |
| Ваш логотип и иконки сайта | `bot/webapp/static/logo.png`, `favicon*` | ❌ нет |
| Свои расширения | `custom_extensions/` | ❌ нет |
| История AI-консультанта | `database/ai_history.db` | ❌ нет |
| Конфиги nginx (домен сайта и резервные домены) | `/etc/nginx/sites-available/` | ❌ нет |
| SSL-сертификаты | `/etc/letsencrypt/` | ❌ нет (проще выпустить заново) |
| Сами VPN-панели (3x-ui) и их клиенты | **на своих серверах** | не затрагиваются |

**Важно:** Telegram-бэкап из админки содержит только базу. Для переезда одной базы недостаточно — используйте скрипт экспорта ниже, он забирает всё перечисленное сразу.

VPN-серверы (ноды с 3x-ui) переезжать не нужно: бот только управляет ими по API. Клиенты продолжают подключаться как раньше, пока вы переносите бота.

---

## 1. Подготовка (за день до переезда)

1. **Домен.** Оставьте тот же домен сайта/WebApp. Ссылки подписки клиентов (в Happ, INCY, Karing, v2rayNG и др.) содержат ваш домен — если его сменить, у всех клиентов перестанут обновляться подписки. Переезжает сервер, а не домен.
2. **Снизьте TTL DNS.** В DNS-записи домена (A-запись) поставьте TTL 300 секунд (5 минут), чтобы переключение прошло быстро. Если запись проксируется Cloudflare (оранжевое облако), TTL у неё автоматический — ничего менять не нужно.
3. **Закажите новый сервер:** Ubuntu 24.04, от 1 vCPU / 2 ГБ RAM / 15 ГБ SSD (см. [README](README.MD#️-требования-к-серверу)). Запишите его IP.
4. **Доступы к панелям.** Если на VPN-серверах (3x-ui) включено ограничение API по IP или фаервол — заранее разрешите **IP нового сервера**. Это самая частая причина «бот не видит серверы» после переезда.
5. Убедитесь, что у вас есть: токен бота (@BotFather), ваш Telegram ID, доступ к DNS домена.

---

## 2. Экспорт со СТАРОГО сервера

Подключитесь к старому серверу по SSH и выполните:

```bash
cd /root/EclipseVPN
git fetch origin && git reset --hard origin/main   # свежие скрипты
bash scripts/migrate_export.sh
```

Скрипт:
- не останавливает бота и делает консистентный снимок базы (SQLite Backup API, безопасно при работающем боте);
- проверяет целостность базы (`PRAGMA integrity_check`);
- собирает `config.py`, `secrets.env`, логотип, расширения, конфиги nginx и systemd, cron;
- кладёт всё в один архив `/root/eclipse_migration_ДАТА.tar.gz` и печатает его SHA256.

> ⚠️ Архив содержит **токен бота и секреты**. Не пересылайте его в мессенджерах и не выкладывайте в открытый доступ. После переезда удалите его с обоих серверов.

Скачайте архив на новый сервер напрямую (с вашего компьютера через `scp`, либо сервер→сервер):

```bash
# с нового сервера:
scp root@СТАРЫЙ_IP:/root/eclipse_migration_*.tar.gz /root/
```

## 3. Установка на НОВОМ сервере

```bash
bash <(curl -sL https://raw.githubusercontent.com/pomah7878-bot/ECLIPSE_VPN/main/install.sh) install ТОКЕН_БОТА ВАШ_TELEGRAM_ID
systemctl stop eclipse-vpn
```

Установщик поставит зависимости, создаст окружение и службу `eclipse-vpn`. Мы сразу останавливаем бота — данные ещё не перенесены.

Дальше — импорт:

```bash
cd /root/EclipseVPN
bash scripts/migrate_import.sh /root/eclipse_migration_ДАТА.tar.gz
```

Скрипт:
- сверяет SHA256, если вы его передали вторым параметром;
- сохраняет текущие файлы нового сервера в `/root/eclipse_pre_migration_ДАТА/` (на случай отката);
- восстанавливает базу, `config.py`, `secrets.env`, логотип, расширения;
- удаляет «хвосты» WAL/SHM, чтобы SQLite не смешала старую и новую базу;
- восстанавливает конфиги nginx (если nginx установлен), проверяет их `nginx -t`;
- **не запускает** бота — это вы делаете вручную на шаге 5.

---

## 4. Домен и SSL на новом сервере

1. Если используется nginx + Let's Encrypt, установите нужное и выпустите сертификат **для каждого домена** (основной и резервные):
   ```bash
   apt-get install -y nginx certbot python3-certbot-nginx
   certbot --nginx -d ВАШ_ДОМЕН
   nginx -t && systemctl reload nginx
   ```
   Пока DNS ещё указывает на старый сервер, certbot не выпустит сертификат. Два варианта: (а) выпустить сертификат уже после переключения DNS (шаг 5), (б) на время переезда скопировать `/etc/letsencrypt/` целиком со старого сервера (`tar czf` → `scp` → распаковать).
2. Проверьте, что `WEBAPP_URL` в `config.py` совпадает с вашим доменом.
3. Резервный домен, созданный через админку, использует тот же шаблон nginx — достаточно, чтобы его DNS указывал на новый IP.

---

## 5. Переключение (самый короткий простой)

Порядок важен. **Нельзя, чтобы два бота с одним токеном работали одновременно** — Telegram отдаёт обновления только одному (ошибка `409 Conflict`), а два планировщика дублируют уведомления, продления и списания.

1. **Старый сервер:** `systemctl stop eclipse-vpn && systemctl disable eclipse-vpn` (при необходимости также `eclipse-ai`).
2. **Старый сервер:** сделайте ещё один экспорт (шаг 2) — он захватит платежи и регистрации последних минут — и повторите импорт на новом (шаг 3). Если простой для вас некритичен, достаточно сделать финальный экспорт **после** остановки бота: тогда ничего не потеряется.
3. **DNS:** переключите A-запись домена (и резервных доменов) на IP нового сервера.
4. **Новый сервер:**
   ```bash
   systemctl start eclipse-vpn
   systemctl is-active eclipse-vpn
   journalctl -u eclipse-vpn -n 50 --no-pager
   ```
5. Если нужен был шаг 4(а) — после того как DNS обновился, выпустите сертификат (`certbot --nginx -d ВАШ_ДОМЕН`).

## 6. Проверка после переезда

- [ ] `/start` в боте отвечает; в админке виден список пользователей и ключей.
- [ ] **Админка → Серверы:** все панели в статусе «онлайн» (если нет — см. пункт про IP в шаге 1).
- [ ] Сайт открывается по HTTPS, вход в личный кабинет работает.
- [ ] Ссылка подписки одного из тестовых клиентов открывается и отдаёт конфиг.
- [ ] Тестовая покупка/пополнение проходит (платёжные провайдеры работают по API, привязки к IP сервера у них нет; если в кабинете ЮKassa/WATA/Platega/Cardlink настроен адрес уведомлений на ваш домен — он не меняется, пока домен тот же).
- [ ] **Админка → Настройки → Лицензия:** лицензия на месте (хранится в базе и `secrets.env`, привязки к IP сервера в коде нет).
- [ ] **Админка → Бэкапы:** запустите бэкап вручную — убедиться, что планировщик работает.
- [ ] Логи без ошибок: `journalctl -u eclipse-vpn -n 100 --no-pager`.

Ничего не нужно менять: у BotFather, в OAuth-кабинетах (Google/Яндекс/VK), Cloudflare Turnstile и Zvonok — всё привязано к **домену**, а не к IP. Если вы меняете ещё и домен — отдельно обновите адреса в этих кабинетах, `WEBAPP_URL` в `config.py` и пересоздайте Mini App/кнопку меню в BotFather.

---

## 7. Откат

Пока старый сервер не удалён, откат занимает минуту: остановите бота на новом, верните A-запись на старый IP, `systemctl enable --now eclipse-vpn` на старом. Не удаляйте старый сервер минимум 3–7 дней.

Пока бот работает на новом сервере, на старом он **остаётся выключенным** — иначе вернётся конфликт двух ботов.

---

## 8. После переезда

1. Верните TTL DNS к обычному значению (3600 и выше).
2. Удалите архив `eclipse_migration_*.tar.gz` с обоих серверов.
3. Проверьте, что ежедневный бэкап (в Telegram) приходит с нового сервера.
4. Если вы использовали cron-бэкап `backup_db.sh` — он перенесён в списке cron (см. вывод экспорта), проверьте `crontab -l`.

## ❓ Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `TelegramConflictError: terminated by other getUpdates request` | Бот ещё запущен на старом сервере. Остановите его (шаг 5.1). |
| Серверы в админке «офлайн» | Панель 3x-ui ограничивает API по IP/фаерволом. Разрешите IP нового сервера. |
| Клиенты не обновляют подписки | DNS ещё не обновился или сертификат не выпущен для домена. Проверьте `curl -I https://ВАШ_ДОМЕН`. |
| Сайт отдаёт 502 | Бот не запущен или `WEBAPP_PORT` в `config.py` не совпадает с портом в конфиге nginx. |
| После импорта бот просит токен/пустой | Не отработал импорт `config.py` — проверьте `/root/EclipseVPN/config.py` и `secrets.env`. |
| Пропал логотип | Скопируйте `logo.png` и `favicon*` из архива в `bot/webapp/static/` (импорт делает это сам). |

---

## ⚠️ Не делайте так

- **Не используйте «Переустановить» в `install.sh` как способ переезда на том же сервере**, не сделав экспорт. Перед переустановкой всегда запускайте `scripts/migrate_export.sh`.
- Не переносите базу простым копированием работающей `vpn_bot.db` — база в режиме WAL, при копировании «на лету» можно получить повреждённый файл. Используйте скрипт экспорта.
- Не запускайте бота на двух серверах одновременно.
